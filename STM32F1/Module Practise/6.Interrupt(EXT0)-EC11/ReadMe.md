# EC11 旋转编码器与 EXTI 中断

本项目使用 EC11 旋转编码器调整一个整数，并通过 OLED 显示当前值。编码器的旋转检测由 `PB0` 的 EXTI0 中断触发，主循环负责读取结果和刷新显示。

## 1. EC11 旋转编码器

### 1.1 六针脚结构

常见 EC11 是“旋转编码器 A/B 两相 + 独立按键”的组合器件，共六个针脚。旋转部分通常有两组三个脚：`A`、`B` 和公共端 `C`；按键部分通常有两组三个脚：`SW1`、`SW2` 和按键公共端。相同名称的脚在器件内部通常已经分别并联，因此六脚版本也可以理解为三个旋转端子和三个按键端子。

不同厂家和封装的脚位顺序可能不同，不能只按外形猜测。接线前应以器件数据手册或万用表通断测试为准：旋转时变化的是 A/B 与 C 之间的通断，按下旋钮时 SW1/SW2 与按键公共端之间导通。

### 1.2 旋转原理

A、B 两路是相位相差约 90 度的方波。旋转时，A/B 不会同时变化，通过“哪一路先变化”可以判断方向。本项目只对 A 相使用双边沿中断，B 相在中断发生时被读取，用于判断方向；一个完整的机械定位约产生两次 A 相边沿，`encoder_get()` 使用 `encoderCount / 2` 换算为显示值。

以本项目的方向约定为例：
![alt text](image.png)
```text
顺时针：A 上升沿时 B 为低，A 下降沿时 B 为高
逆时针：A 上升沿时 B 为高，A 下降沿时 B 为低
```

实际顺逆时针方向取决于 A/B 接线。如果显示方向与预期相反，交换 A、B 两根信号线，或反转计数加减逻辑即可。

### 1.3 防抖：编码器也需要按键思路

EC11 是机械触点，触点闭合或断开时会在很短时间内反复跳变。旋转时，这些跳变可能被误认为多个边沿；按键部分按下或松开时也会产生同样的抖动。因此，旋转编码器的按键输入可以沿用普通按键的防抖方法：

- 软件延时防抖：检测到变化后延时约 10--20 ms，再次读取确认状态。
- 定时采样防抖：每隔固定时间采样，连续多次得到相同状态后才确认事件。
- 状态机防抖：只接受合法的 A/B 状态迁移，忽略不符合相序的跳变。
- 硬件防抖：使用 RC 滤波或施密特触发器，但参数过大可能削弱边沿。

本项目当前只对 A 相使用双边沿中断，通过 `lastA` 判断边沿，再读取 B 相判断方向；该方案结构简单，但对机械抖动的过滤能力有限。若出现一次旋转跳多个数，可增加时间窗口或定时采样防抖。

## 2. EXTI 中断回顾

EXTI（External Interrupt/Event Controller）用于把 GPIO 的边沿变化转换为 CPU 中断。STM32F1 的 GPIO 引脚先通过 AFIO 映射到 EXTI 线路，再配置触发方式，最后由 NVIC 打开对应的 IRQ 通道。

本项目的配置步骤如下：

1. 开启 GPIOB 和 AFIO 时钟。
2. 将 PB0/PB1 配置为上拉输入 `GPIO_Mode_IPU`。
3. 通过 `GPIO_EXTILineConfig(GPIO_PortSourceGPIOB, GPIO_PinSource0)` 将 PB0 映射到 EXTI0，PB1 不连接 EXTI，只作为普通输入读取。
4. 将 EXTI0 配置为中断模式，并同时响应上升沿和下降沿。
5. 在 NVIC 中使能 `EXTI0_IRQn`。
6. 在中断服务函数中读取 GPIO、处理事件、清除 EXTI 挂起标志。

这里有一个重要限制：同一条 EXTI 线路同一时刻只能映射一个端口的同编号引脚。例如 EXTI0 可以选择 PA0、PB0 等其中一个，不能同时监听多个端口的 0 号引脚。

### 当前检测逻辑

当前只有 A 相触发中断，B 相只在中断中读取：

```c
if (lastA == 0 && currentA == 1) {
    currentB == 0 ? encoderCount++ : encoderCount--;
} else if (lastA == 1 && currentA == 0) {
    currentB == 1 ? encoderCount++ : encoderCount--;
}
lastA = currentA;
```

### AB 状态检测扩展

如果需要更强的抗抖能力，可以让 A、B 两相都触发中断，记录完整 AB 状态，再用状态转移表判断：

```text
当前代码的正向：00 -> 10 -> 11 -> 01 -> 00
反向状态：      00 -> 01 -> 11 -> 10 -> 00
```

非法跳转可以直接丢弃，机械抖动造成的来回跳变也不会轻易产生有效计数。该方案属于本项目的扩展方向，不是当前代码的实现方式。

## 3. 项目架构与调用关系

```text
startup_stm32f10x_md.s
    └─ Reset_Handler
        ├─ SystemInit()
        └─ main()

main.c
    ├─ OLED_Init()
    ├─ encoder_init()
    └─ while(1)
        ├─ encoder_get()
        └─ OLED_ShowSignedNum()

EC11.c
    ├─ GPIO / AFIO / EXTI / NVIC 初始化
    ├─ EXTI0_IRQHandler()
    └─ encoder_get()
```

各层职责如下：

- `src/main.c`：应用入口，只关心初始化、读取数值和显示。
- `src/drive/src/EC11.c`：EC11 硬件驱动，负责初始化 GPIO 和中断，并维护编码器计数。
- `src/drive/src/OLED.c`：通过 PB11/PB12 软件模拟 I2C，负责 OLED 初始化和显示。
- `hal/STM32F10x_StdPeriph_Driver`：提供 GPIO、RCC、EXTI、NVIC 等标准外设接口。
- `src/startup_stm32f10x_md.s`：提供启动代码和中断向量表。

### 中断调用过程

执行顺序如下：

1. `EXTI_GetITStatus()` 确认确实是 EXTI0 产生了挂起请求。
2. 读取 PB0 的当前状态，与 `lastA` 对比，确定是上升沿还是下降沿。
3. 读取 PB1 的状态，根据 A/B 相位关系判断顺时针或逆时针。
4. 修改 `volatile int16_t encoderCount`。
5. 保存当前 A 相状态，为下一次边沿判断做准备。
6. 调用 `EXTI_ClearITPendingBit()` 清除挂起标志，允许后续边沿再次触发中断。

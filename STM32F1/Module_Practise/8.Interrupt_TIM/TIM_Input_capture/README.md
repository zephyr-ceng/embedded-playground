# STM32F103 输入捕获超声波测距

本项目使用 STM32F103C8T6、TIM1 输入捕获和四脚超声波测距模块（例如 HC-SR04）测量距离，并通过软件模拟 I²C 驱动 OLED 显示结果。工程由 STM32CubeMX 生成基础初始化代码，使用 STM32 HAL 和 CMake 构建。

> **说明：**本文按当前工程源码说明测量流程，并在[当前代码注意事项](#当前代码注意事项)中记录已修复的问题及仍需留意的事项。

## 1. 硬件连接

| 功能 | STM32F103 引脚 | 说明 |
| --- | --- | --- |
| 超声波模块 TRIG | PA10 | 推挽输出，发送触发脉冲 |
| 超声波模块 ECHO | PA8 / TIM1_CH1 | 输入捕获输入；TIM1_CH2 配置为 TI1 间接输入，也捕获该引脚信号 |
| OLED SCL | PB11 | 软件模拟 I²C 时钟 |
| OLED SDA | PB12 | 软件模拟 I²C 数据 |
| 电源与地 | 依模块规格连接 | STM32、OLED 和测距模块必须共地 |

确认模块 ECHO 输出电压与 MCU 引脚允许电压相符。若使用 5 V 供电的测距模块，应查阅具体模块和芯片板卡规格；必要时对 ECHO 做电平转换或分压保护。

## 2. 时钟配置

`SystemClock_Config()` 中使用外部高速时钟 HSE，经 PLL 倍频后作为系统时钟。工程配置假设 HSE 为 8 MHz：

- PLL 倍频系数：9
- SYSCLK、HCLK、PCLK2：72 MHz
- APB1 分频：2，因此 PCLK1 为 36 MHz
- APB1 定时器时钟为 72 MHz（APB 分频不为 1 时，STM32F1 定时器时钟为 PCLK 的 2 倍）
- TIM1 位于 APB2，总线分频为 1，因此 TIM1 输入时钟为 72 MHz

如果实际板载晶振不是 8 MHz，必须相应修改系统时钟配置；否则 CPU、TIM1 和 DWT 延时的实际频率都会与本文计算不同。

## 3. TIM1 输入捕获配置

配置位于 `Core/Src/tim.c` 的 `MX_TIM1_Init()`：

| 配置项 | 当前值 | 作用 |
| --- | --- | --- |
| 定时器 | TIM1 | 16 位高级控制定时器 |
| 预分频器 PSC | `72 - 1` | 计数频率 $72\text{ MHz}/72=1\text{ MHz}$ |
| 自动重装 ARR | `65535` | 计数范围 0～65535，溢出周期为 65.536 ms |
| 计数方向 | 向上计数 | 每次计数约为 1 μs |
| CH1 输入 | TI1 直接输入，上升沿 | 在 ECHO 上升沿把计数器值锁存到 CCR1 |
| CH2 输入 | TI1 间接输入，下降沿 | 在同一 ECHO 信号下降沿把计数器值锁存到 CCR2 |
| 输入滤波 | 0 | 当前未启用数字滤波 |

CH1 与 CH2 捕获的是同一根 PA8/ECHO 信号的两个不同边沿。CH1 使用 `HAL_TIM_IC_Start()`，只开启硬件捕获、不请求 CH1 中断；CH2 使用 `HAL_TIM_IC_Start_IT()`，在下降沿产生 TIM1 捕获比较中断。

### 捕获处理流程

清除旧捕获数据和标志，计数器归零
	→ PA10 输出 10 μs 触发脉冲
	→ ECHO 上升沿：CH1 将计数值保存到 CCR1
	→ ECHO 下降沿：CH2 将计数值保存到 CCR2，并触发中断
	→ 中断读取 CCR1、CCR2，置位 `captureComplete`
	→ 主循环检测到捕获完成后计算并显示距离；40 ms 超时则显示 0

`TIM_FLAG_CC1` 是硬件捕获标志，表示 CCR1 已有一次捕获结果。它不是软件完成标志；在 CH1 不开启中断的设计中，用它确认下降沿到来前已有上升沿捕获。

### `captureComplete` 的作用

`captureComplete` 是 `tim.c` 中定义、在 `tim.h` 中声明的 `volatile` 全局变量：

- 初始值和每轮测量开始时应为 0，表示尚未获得完整回波脉冲。
- CH2 下降沿中断在确认 CH1 上升沿捕获后，将两次捕获值保存，并置为 1。
- 主循环据此避免把未完成测量或上次测量数据当成本次结果。
- `volatile` 告知编译器该值可能在中断中异步修改，主循环读取时不可假定它在普通代码中保持不变。

## 4. 超声波测距原理和计算

四脚超声波模块通常包含 VCC、TRIG、ECHO、GND。TRIG 接收满足模块时序要求的触发脉冲后，模块发射超声波；声波遇到目标后反射。ECHO 高电平持续时间通常表示声波从发射到接收的往返传播时间。

设 ECHO 高电平时间为 $t$，声速为 $c$，目标距离为 $d$。声波走了往返路程，因此：

$$
d=\frac{c\times t}{2}
$$

当前 TIM1 计数频率为 1 MHz，因此：

- 捕获计数差每 1 个计数约等于 1 μs。
- 声速按约 340 m/s 估算，即 0.034 cm/μs。
- 距离以厘米表示时，$d(\text{cm})=t(\mu\text{s})\times0.034/2$。

代码使用 `uint16_t` 计算两次 16 位捕获值的差值，可自然处理一次计数器回绕（模 $65536$ 差值）。当前有效脉宽上限为 40000 μs，小于计数器的 65536 μs 回绕周期，因此在该上限内最多发生一次回绕。零脉宽、未完成捕获或超过 40000 μs 的结果视为无效，返回 0。

例如，若捕获到 1000 个计数，则时间约为 1000 μs，计算距离约为 $1000\times0.034/2=17$ cm。40000 μs 是软件设置的无效脉宽上限，不是定时器的最大计数值；按 340 m/s 换算，对应约 680 cm 单程距离，实际模块的有效量程一般小得多，应按传感器规格调整。

## 5. 微秒延时原理与配置

`delay_us()` 位于 `Core/Src/delay.c`，接口声明在 `Core/Inc/delay.h`。它使用 Cortex-M3 的 DWT（Data Watchpoint and Trace）周期计数器 `DWT->CYCCNT`：

1. 使能 CoreDebug 跟踪功能和 DWT 周期计数器。
2. 读取当前周期计数作为起点。
3. 根据 `SystemCoreClock` 计算目标 CPU 周期数：`(SystemCoreClock / 1000000) * us`。
4. 等待周期计数差达到目标值。

系统时钟为 72 MHz 时，每微秒约有 72 个 CPU 周期，所以 `delay_us(10U)` 用于产生约 10 μs 的 TRIG 高脉冲。该延时依赖 DWT 和 `SystemCoreClock` 配置准确；如果更换 MCU、编译环境或时钟频率，应确认目标芯片支持 DWT，并检查系统时钟变量已正确更新。该函数是忙等延时，调用期间 CPU 不执行其他任务；函数调用和 GPIO 操作开销也会使实际脉冲略长于理想值。

主循环在触发后等待 `captureComplete`，每轮使用 `HAL_Delay(1U)` 暂让 CPU，并以 40 ms 作为超时；捕获完成后更新 OLED，再等待 100 ms 后开始下一轮。`HAL_Delay()` 的单位是毫秒，基于 HAL 的 SysTick。

## 6. 影响测量的因素

- **温度：**影响最大。空气中声速近似为 $c\approx331.3+0.606T$ m/s（$T$ 为摄氏温度）。温度变化会带来比例误差；固定使用 340 m/s 只是近似值。
- **湿度：**湿度会影响空气的声速和超声波衰减，通常小于温度影响，但在长距离或精密测量时也应考虑。
- **噪声和电气干扰：**电源纹波、地线不良、长导线、附近电机或开关电源可能造成假边沿或不稳定捕获。应确保共地、供电稳定、信号线短且走线合理。
- **回声与多径反射：**墙面、地面或周边物体的反射可能使模块接收到非目标回波。保持传感器与目标正对，避免附近障碍物。
- **目标表面和角度：**倾斜、柔软、吸声或面积较小的目标会反射较弱，可能漏测；硬而平整且正对传感器的表面通常更容易测量。
- **量程和盲区：**超出模块标称量程可能无回波；目标太近时，发射振铃和接收恢复时间会形成盲区。应以具体模块手册为准。
- **输入滤波：**当前 `ICFilter = 0`，没有对 ECHO 做定时器数字滤波。噪声严重时可以按 TIM1 时钟和信号特性配置滤波，但滤波过强会延迟边沿或漏掉窄脉冲。
- **采样间隔：**测量后固定等待 40 ms，再 OLED 更新并等待 100 ms，完整测量周期约 140 ms。过快重复触发可能让上一轮残余回波干扰下一轮。
- **捕获上限和溢出：**TIM1 计数器每 65.536 ms 回绕；当前 40 ms 的软件上限可限制合理脉宽，但仍应确保捕获到的是同一发射周期的有效回波。

## 7. 当前代码注意事项

当前相关的测量流程问题已在代码中处理：

1. 已删除 `main()` 内遮蔽全局变量的 `risingEdge`、`fallingEdge` 局部定义；主循环与捕获回调现在使用同一组 `volatile` 全局变量。
2. 每轮开始时清除 CC1、CC2、CC1OF、CC2OF 标志和 TIM1_CC 的 NVIC 挂起状态，避免旧捕获遗留。
3. 等待流程现在检查 `captureComplete`，捕获完成即继续；40 ms 未完成则超时，不再固定等待完整 40 ms。
4. 捕获值和完成标志由中断与主循环共享，均声明为 `volatile`。若未来改变 ISR 行为或增加并发访问，读取多个捕获值时应考虑使用一致性快照。
5. `return_distance_cm()` 中的 40000 μs 是软件过滤上限，应按具体传感器的有效量程调整；它不代表模块保证能测到约 6.8 m。

## 8. 工程构建

工程使用根目录的 `CMakeLists.txt` 和 `CMakePresets.json`，默认提供 `Debug`、`Release` 配置；工具链文件位于 `cmake/gcc-arm-none-eabi.cmake`。在 VS Code 中选择相应 CMake preset 并构建 `TIM_Input_capture` 目标即可。产物为 STM32 可执行文件 `.elf`，实际下载和调试还需配置对应的 ST-Link/OpenOCD 工具链。

主要源码：

- `Core/Src/main.c`：系统时钟、触发、测量循环和 OLED 显示。
- `Core/Src/tim.c`、`Core/Inc/tim.h`：TIM1 初始化、捕获中断和距离计算。
- `Core/Src/delay.c`、`Core/Inc/delay.h`：基于 DWT 的微秒延时。
- `Core/Src/OLED.c`、`Core/Inc/OLED.h`：OLED 软件 I²C 和显示接口。
- `TIM_Input_capture.ioc`：STM32CubeMX 外设、引脚及总线时钟配置。
